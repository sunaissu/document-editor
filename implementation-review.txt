Document editor implementation review
11 October 2026

Replaced duplicate parsers with one shared markdown-it parser, added regression-backed Markdown serialization fixes, protected composing input, rebased stale collaborative text, and added local-only shared history. Added find/replace, an outline, task/table/image insertion, six heading levels, an accessible link dialog, and print styling. The tools reuse the current theme; insertion controls are now visible and find/outline sections expand on demand.

Validation: npm test passes 29 tests; type check, CJS/ESM/type builds, playground build, and package dry-run pass. Runtime npm audit reports 0 vulnerabilities. Browser checks cover typing, replacement, tables, tasks, modal focus/Escape, source caret movement, peer-safe undo, composition rebasing, and desktop/mobile light/dark layouts.

Release status: locally validated changes, not published. Visual editing remains a Markdown-normalizing editor, not a lossless editor for arbitrary extensions. Source mode is the preservation path. Natural IME input, other browsers, live provider reconnects, and very large documents need wider coverage before broad release certification.

Selection formatting and toolbar redesign — 2026-10-12

Replaced the two-row ribbon with one row of dropdowns. Lists stay grouped; table editing appears as a menu when a cell is selected. More contains secondary groups on narrow screens. Find and Outline retain their docked panels.

Selected visual text now has a contextual toolbar for bold, italic, strike, inline code, and links. Marks are read across the actual range, including mixed states. Partial inline-code removal preserves the unselected code. Menu commands restore the selected range; keyboard focus can move into the selection toolbar with Alt+F10. Arrow keys, Home/End, and Escape are supported. Collapsing selection, moving focus outside, scrolling, or resizing dismisses the bubble. Composition suppresses it. Caret state checks do not traverse the document. Removed obsolete ribbon styles; no dependencies added.

Research: Notion and Word use selection formatting menus. Tiptap separates fixed document controls, selection menus, and slash insertion. This implementation adopts that interaction pattern without adding an editor framework. WAI-ARIA toolbar and toggle-button patterns inform focus and state handling.
